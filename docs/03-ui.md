# UI

## Layout

Top: Projects / Profiles tabs
Projects tab: two-column browser (Projects left, Sessions right) with a one-cell
gap between panes; `Tab`/`←`/`→`
moves focus between the columns
Profiles tab: named Profiles above, activation snapshots below, separated by a
one-cell gap
Bottom: Status Bar + Key Hints

Token usage does not add a third primary column in the first implementation.
The existing two-column layout remains the default to preserve narrow terminal
behavior.

### Duplicate Project Names

Project rows normally display the project directory name only. When two or more
loaded projects have the same directory name, each colliding row displays its
direct parent directory and project directory, for a maximum of two path
segments. For example, `/workspace/team-a/api` and `/workspace/team-b/api` are
shown as `team-a/api` and `team-b/api`. Projects whose directory names are
unique keep the shorter single-segment label, such as `api`.

### Project Row Token Summaries

Each real project row shows compact aggregate token usage after the project name
and session count:

- `cowboy (8) 12.3K` — all 8 sessions have usage data; the total is complete
- `cowboy (10) 12.3K+` — 8 of 10 sessions have usage data; `+` means the real
  total is at least this value
- `cowboy (5) Unknown` — the project has sessions but none have usage data
- `cowboy (0) 0` — the project is empty

The synthetic `Open Here` row does not represent a loaded project and shows no
token usage.

### Token Total Definition

The project aggregate and session total both use the same four-component sum:

`input tokens + output tokens + cache creation tokens + cache read tokens`

All values go through the same compact formatter: raw integers below 1 000, one
decimal `K` below 1 000 000, and one decimal `M` at or above 1 000 000.

### Session Info Token Display

The Session Info modal shows the selected session's token breakdown:

- Input Tokens
- Output Tokens
- Cache Write
- Cache Read
- Total Tokens (sum of all four categories, same compact formatter)

When usage data is unavailable, the modal shows `Token Usage: Unknown`.

## Popups

- Session Info
- Rename
- Delete Confirmation: `Ctrl+D` opens the dialog; `Enter`, `y`, or a second
  `Ctrl+D` confirms; `q`, `Esc`, or `n` cancels.

Session Info should include detailed token usage and estimated cost when local
session `usage` data is available:

- Model
- Input tokens
- Output tokens
- Cache creation tokens
- Cache read tokens
- Server-side tool usage, if present
- Estimated cost
- Accuracy status, such as `usage-based estimate`, `token-only`, or `unknown`

Token values in Session Info use the same compact display as the session list:
raw integers below `1_000`, one decimal `K` below `1_000_000`, and one decimal
`M` at or above `1_000_000`.

## Primary Actions

Enter in Projects: New Session in the selected project, inheriting the parent process environment
Enter on `Open Here`: New Session in the current working directory without creating a project settings file
Enter in Sessions: Resume the selected session, inheriting the parent process environment
`[` / `]`: cycle the three top-level tabs
Enter in Profiles: activate the focused Profile or snapshot
n New Session in the selected project from the Sessions pane
i Info
r Rename
Ctrl+D Delete
  - in `Projects`: delete the selected project and all discovered sessions under it
  - in `Sessions`: delete the selected session only
  - `Ctrl+D` in the confirmation dialog confirms deletion
  - after confirmation, deletion runs in the background and the status bar
    changes to `Deleting`; the lists remain visible until a successful refresh
q / Esc Quit
/ Search

### Deletion In Progress

After a delete confirmation is accepted, the TUI remains visible and responsive
while the filesystem operation runs. The status badge identifies the deletion
target and asks the user to wait. The key-hint row becomes a waiting-only hint:
normal navigation and action hints are not shown.

During this state, all application keyboard actions are ignored. In particular,
`q` and `Ctrl-C` do not exit; they reaffirm that deletion is in progress. `Esc`
is also disabled and does not exit. This prevents a second delete, rename,
launch, focus change, or configuration action from acting on stale list state.
Once the worker finishes, normal shortcuts return. A successful completion
refreshes the project list and shows the normal delete success status; a failed
completion keeps the current list and shows an error toast.

## Key Hints

- Bottom key hints change with the active pane
- In `Projects`, the hint row shows `Enter New Session`; selecting `Open Here` uses the current working directory
- In `Sessions`, the hint row shows `Enter Resume`
- In Profiles, the hint row shows move, select, activate, create, and delete actions
- In `Projects`, the hint row shows `Ctrl+D Delete Project`
- In `Sessions`, the hint row shows `Ctrl+D Delete Session`
